五、整体架构布局（五层纵深）

自上而下单向依赖，禁止反向引用：路由层 → 业务域层 → 数据访问层 → 基础设施层 → 数据库。这是目录整理方案落地后的稳态。
① 路由层 app/
薄页面 · 每路由仅 page.tsx · 服务端解析 searchParams + 鉴权 + 调模块 queries · /login/(dashboard)/… 共 11 页
▼ 读：调模块 queries（RLS 客户端） ·  写：调模块 actions（Server Action）
② 业务域 modules/
一个后台功能 = 一个自包含目录 · index.ts 显式导出types.tsschema.ts zodpolicy.ts 授权mapper.ts 映射queries.ts 读commands.ts 写actions.ts 动作components/ 视图
▼ 经受控客户端工厂（禁止页面/组件直连）
③ 数据访问 storage/
getSupabasePublicClient 匿名getSupabaseRlsClient 用户态（读 → RLS）getSupabasePrivilegedClient service-role（写专用）
▼ RLS 兜底 + 行级安全
④ 基础设施 lib/
lib/auth 集中权限层 policy/permissions/context/errorsdb-types.ts 手写类型分页/查询工具components/ui 通用 UI（无业务）
▼ schema 唯一来源
⑤ 数据库 supabase/
migrations/ SQL 迁移（001–010）· 表结构 / RLS 策略 / RBAC 角色权限 / 事务 RPC —— 全栈类型的唯一事实源
